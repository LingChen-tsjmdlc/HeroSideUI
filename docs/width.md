# 组件宽度约定

这一页回答三个问题：组件默认多宽？我自己设宽会不会被组件抢回去？`full_width` 是什么意思？

## 先说结论

1. **组件分两类**，和官方 HeroUI 一致：
   - **内容型**：宽度恰好等于内容，放在竖排布局里也不会被拉宽。例：Button、Chip、Checkbox。
   - **铺满型**：宽度跟着外面的容器走。例：Input、Select、Table。
2. **你设的宽度永远优先**。`setFixedWidth` / `setMinimumWidth` / `setMaximumWidth` 直接生效，组件不拦截、不偷偷抬高。
3. **输入框的 320 只是"建议宽度"**，不是最小宽度。没人管它时是 320，你设成 80 它就是 80。全库只有这一个数，不分 sm / md / lg。
4. **`full_width=True` 就是"撑满"**，默认值照官方：有的组件默认撑满，有的默认不撑。

## 官方是怎么做的

官方是网页，输入框没有任何像素宽度，宽度全由外层容器决定（示例里都是外面包一个 `max-w-xs`）。官方只有三个地方设了最小宽度：

| 组件 | 官方最小宽度 |
| --- | --- |
| Button | 按尺寸 64 / 80 / 96（含左右留白与边框的总宽，本库已对齐） |
| Select | 仅当 `fullWidth=false` 时 160 |
| NumberInput | `fullWidth` 默认 true | 320 | 0（最小提示 95） | 无 | Expanding | 同样用统一建议宽度 |

Qt 做不到网页那种"天然铺满"：控件没人撑就会缩成一条线。所以我们补了一个**建议宽度**，只影响"没人管它时有多宽"（`sizeHint`），从不当最小宽度用。

这个数是 **320**，来源是官方文档示例：输入类组件的示例里 `max-w-xs`（= 320px）出现了 139 次，`max-w-xl` 6 次，`max-w-sm` 2 次。它放在 `themes/width.py` 的 `SUGGESTED_WIDTH`，输入类、Slider、Progress、CodeEditor、Divider 共用。

## 三个宽度概念

| 概念 | 意思 | 谁来定 |
| --- | --- | --- |
| 建议宽度 | 没人管它时有多宽 | 组件自己给，见下面的总表 |
| 最小宽度 | 再窄也不能窄过这个 | 官方只有 Button 和不撑满的 Select 有；其余让 Qt 按内部零件自己算 |
| 最大宽度 | 再宽也不能宽过这个 | 不设。由外层容器和 `full_width` 决定 |

## `full_width` 的默认值

| 默认撑满（`True`） | 默认不撑满（`False`） | 没有这个参数 |
| --- | --- | --- |
| Input、Textarea、Select、DateInput、TimeInput、NumberInput、DatePicker、DateRangePicker、Table、Accordion | Button、Card、Tabs、InputOtp | Autocomplete、Alert、Progress、Slider、Divider（官方写死撑满） |

`full_width=False` 的效果：

- 内容型组件：宽度恰好等于内容。
- Select：回到建议宽度，并且至少 160px。
- Accordion：宽度跟内容走。
- 其余输入类：回到建议宽度。

## 在布局里的表现

| 布局 | 铺满型 | 内容型 |
| --- | --- | --- |
| 竖排（`QVBoxLayout`） | 铺满整行 | 只有内容那么宽 |
| 横排 + 右侧弹簧 | 建议宽度 | 内容宽 |
| 并排两个，没有弹簧 | 平分 | 各自内容宽 |

注意：**`full_width=False` 的铺满型组件放进竖排布局，仍然会铺满整行**。官方网页里同理，`fullWidth=false` 并不会让输入框变窄。想让它窄，给它设宽，或者外面套一个限宽的容器。

## 你自己设宽

```python
inp = Input(label="Name")
inp.setFixedWidth(150)      # 就是 150，不会被内部元素撑大
inp.setMaximumWidth(400)    # 最多 400
inp.set_width(150)          # 等价于 setFixedWidth(150)
```

- Select、Autocomplete、DatePicker 这类"输入框外面再包一层"的组件，设宽后内部输入框会一起变，不需要你转发。
- 设得太窄（比如 40px）时，内容会被裁切，这是你选的宽度；组件不会替你加下限。

## 全部组件总表

数字都是离屏实测的（默认字体、md 尺寸，字体不同会有出入）。

**三列怎么读**：

- **默认宽度**：没人设宽、也没被拉伸时的宽度。
  - **内容宽**：内容多宽就多宽。
  - **建议 320**：只在横排加弹簧、没人撑它时用；竖排铺满整行，并排平分。
  - **固定 px**：尺寸本身就是外观。
- **最小宽度**：被布局挤压时最窄缩到多少。
  - **固定 px**：写死的数字。
  - **= 内容宽**：压不窄。
  - **零件下限**：不是我们定的，是内部零件（左右留白、图标、输入区）加起来的数。随尺寸档、图标、字体变，**不随输入的文字变**；你手动设宽不受它限制。官方输入框没有最小宽度，所以这里不加保底值。
- **最大宽度**：除固定尺寸的组件外都没设上限。内容型的策略是 `Maximum`，布局拉不宽它们，效果上等于内容宽。

| Accordion | 内容宽；竖排铺满整行 | = 内容宽 | 无 |
| Table | 内容宽；竖排铺满整行 | = 内容宽 | 无 |

| CodeBlock | 内容宽 136；竖排铺满整行 | = 内容宽 | 无 |
| Progress | 建议 320 | 零件下限 40 | 无 |
| Slider | 建议 320 | 零件下限 8 | 无 |
| CodeEditor | 建议 320 | 固定 120（用户指定，官方没有这个组件） | 无 |
| Divider | 建议 320（沿长边：水平线是宽，垂直线是高）；竖排（水平线）/ 横排（垂直线）铺满 | 0 | 无 |
| Skeleton | 没有宽度（官方也没有），竖排铺满整行；横排加弹簧时是 0 | 0 | 无 |
| ScrollShadow | 没有宽度，竖排铺满整行 | 零件下限 50 | 无 |

Skeleton、ScrollShadow 自己不带宽度（官方 Skeleton 也没有，宽度由用户指定），要放在能给它宽度的布局里（竖排，或横排里设宽 / 设拉伸比例）。

Divider 对应官方的 `w-full` / `h-full`（占父容器 100%）。Qt 没有百分比，所以在"没人撑它"的布局里给一个建议长度 320：横排加弹簧时水平线是 320，而不是整行；想铺满整行，放进竖排或去掉弹簧。

### 浮层（不进上面的规则）

| 组件 | 宽度 |
| --- | --- |
| Popover / Tooltip | 内容宽 |
| Dropdown 菜单 | 最小固定 200，不分档（官方 `min-w-[200px]`），不小于触发器宽度 |
| Drawer | 最大宽按档位 320 … 1024 |
| Toast | 固定 356，窄窗口兜底最小 220 |

## 给贡献者：新组件怎么做

1. 先看官方这个组件是 `w-full` 还是 `inline-flex` / `max-w-fit`，决定它是铺满型还是内容型。
2. 内容型：水平策略用 `Maximum`；`full_width` 才改 `Expanding`。要保证 `minimumSizeHint` 等于 `sizeHint`，否则会被布局压窄。
3. 输入类：基类加上 `SuggestedWidthMixin`，用 `set_suggested_width(...)` 给建议宽度；外框用 `release_width_floor(wrapper)` 解除下限。**不要**重写 `setFixedWidth` 等方法，也不要用 `setMinimumWidth` 当默认宽度。
4. 默认值照官方 `defaultVariants.fullWidth`，没有就不加参数。
5. 加到上面的总表里。

## 数字的来历

宽度相关的每个数字，只能是下面三类之一：

1. **官方有这个数** → 照抄官方，注释写明出处。例：Button 最小宽 64 / 80 / 96、Dropdown 菜单 200、Switch 40 / 48 / 56、Calendar 256、Toast 356。
2. **官方没有，但 Qt 必须补** → 全库只有**一个**：`SUGGESTED_WIDTH = 320`（输入类、Slider、Progress、CodeEditor、Divider 的建议宽度；Radio 卡片借它当上限）。
3. **其余** → 按内容算，不写死。例：Tabs 标签宽、Table 复选框列宽。

新增或修改宽度数字时，先判断它属于哪一类；说不出来历的数字不要加。
