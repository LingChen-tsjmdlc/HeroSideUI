# ARCH-05 对象与全局设施的所有权：完成记录

状态：**已完成**。生命周期边界的四项补丁（见“评审补丁”）已修复并验证。实施日期：2026-11-13。实施基线：0.17.2（ARCH-04 之后）。

## 问题是什么

库里有三类东西需要说清楚"谁创建、谁持有、什么时候释放"：

| 类别             | 核对到的情况                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 组件登记簿       | 主题管家和字体管家各写了一套弱引用登记。广播时一句 `except Exception: pass` 把所有错误吞掉，组件自己的真实错误看不到                                                |
| 应用级设施       | 库在 `setup()` 时改了 QApplication 的调色板、样式表、事件过滤器，并把 fd 2 接到管道。滚动条样式和平滑滚动有卸载，**调色板和 libpng 过滤没有**，也没有统一的撤销入口 |
| 调用方传入的控件 | 38 个传入控件的接口，替换旧控件时的做法不统一，见下                                                                                                                 |

## 能力与拥有者

| 能力             | 拥有者与入口                            | 消费者                      |
| ---------------- | --------------------------------------- | --------------------------- |
| 弱引用登记与广播 | `core/_registry.py` 的 `WidgetRegistry` | ThemeProvider、FontProvider |
| 撤销应用级设施   | `HeroSideUIProvider.teardown()`         | 嵌入宿主（如 DCC）的场景    |
| 输入类槽位填充   | `_shared/fields` 的 `fill_slot`         | Input、DateInput、Textarea  |

## 组件登记簿

| 项                                                    | 行为                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 组件销毁                                              | 弱引用自动脱离                                                                               |
| 广播时 Qt 对象已失效（`shiboken6.isValid` 为假）      | 静默注销                                                                                     |
| 广播时其他异常，包括存活组件自己抛出的 `RuntimeError` | 组件保持登记，告警一次（同一组件类型与错误只告警一次），带出组件类型与错误，继续通知其余组件 |
| 不变的部分                                            | 广播顺序、注册时立即推送、`registered_count`、`is_registered`、`in` 判断                     |

## 撤销应用级设施

`HeroSideUIProvider.teardown()` 只撤销库自己装的东西：

| 设施                                      | 做法                                                                                                                 |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| QApplication 的 Window、WindowText 调色板 | 首次改动前按 Active、Inactive、Disabled 分别记下画刷，teardown 时逐组写回，只动这两个角色；再次 `setup()` 时恢复同步 |
| 滚动条样式                                | 移除样式表片段与过滤器；只在已创建单例时执行，不会为了卸载而先安装                                                   |
| 平滑滚动                                  | 摘掉全局过滤器                                                                                                       |
| libpng 警告过滤                           | 把 fd 2 指回原目标，过滤线程读到 EOF 后写完剩余内容并释放自己持有的描述符，`uninstall()` 等待其退出                  |
| 启动标志                                  | 复位，之后可再次 `setup()`                                                                                           |

不处理：已创建的组件、已设置的字体、字体管家登记。它们属于应用本身。

## 调用方传入的控件

规则：**控件交给组件后归组件所有，组件替换它时销毁旧控件。** 有一类接口保留“摘下归还”，原因是同一个接口既能传图标名字符串，也能传调用方自己的控件，组件需要区分库自建的图标和调用方的控件。

| 做法               | 接口                                                                                                                                                                                                                                                                                                                                    | 本次处理                                                    |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 替换并销毁（规则） | Accordion `set_content`；Drawer `set_content`；Listbox 项 `set_start_content`、`set_end_content`；Listbox `set_top_content`、`set_bottom_content`；Dropdown 同名两个；Popover `set_content`；Table 的 `set_top_content`、`set_bottom_content` 与单元格 `set_content`；Tabs `set_custom`；Toast `set_end_content`；Tooltip `set_content` | 行为不变，补文档                                            |
| 此前只叠加，不替换 | Alert `set_start_content`、`set_end_content`                                                                                                                                                                                                                                                                                            | **改为替换并销毁旧控件**，`None` 清空；构造参数走同一个实现 |
| 摘下归还（例外）   | Input、DateInput（含 TimeInput）、Textarea 的前后内容槽；Badge `set_widget`；Slider 四个内容接口                                                                                                                                                                                                                                        | 行为不变，补文档说明例外                                    |
| 追加型，不涉及替换 | Drawer、ScrollShadow 的 `add_widget`、`insert_widget`                                                                                                                                                                                                                                                                                   | 不适用                                                      |
| 传入的是工厂函数   | Markdown `set_inline_widgets`                                                                                                                                                                                                                                                                                                           | 不适用，控件由 Markdown 自己创建与销毁                      |

另外修了两处：

| 问题                                                                                                                                                | 处理                                              |
| --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Slider 四个接口替换时，由字符串生成的内部图标既不销毁也不归还，会残留在内存里                                                                       | 内部图标销毁，调用方的控件继续归还                |
| Textarea 有一份与共享层相同的 `_fill_slot`，漏掉了“同一控件已在槽位则不重新挂接”的保护，Textarea 里放发送按钮时可能在失去焦点重排时吞掉鼠标释放事件 | 合并为共享函数 `fill_slot`，Textarea 获得这条保护 |

## 评审补丁

交付后的评审发现生命周期有四处没闭合，都已复现、修复并加了回归测试。

| 问题                                                | 原因                                                                                                                                         | 修复                                                                                                                                                                    |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setup` → `teardown` → `setup` 后全局调色板不再同步 | `teardown` 关闭了同步，`setup` 没有重新开启；相同主题再次初始化时 `set_mode` 直接返回，也不会触发同步                                        | `ThemeProvider` 新增 `acquire_app_palette()`，`setup()` 调用它：恢复释放前的开关并立即按当前主题同步；用户用 `set_auto_app_palette()` 的设置优先，不会被误开            |
| `teardown` 把宿主调色板写坏                         | 只保存了 Window、WindowText 各一种颜色，还原时用 `setColor(role, color)` 同时覆盖了三个颜色组                                                | 分别保存 Active、Inactive、Disabled 的画刷，逐组写回，只写这两个角色，宿主之后改动的其他角色保持不变                                                                    |
| 存活组件被静默注销                                  | 登记簿把所有 `RuntimeError` 都当成对象已销毁                                                                                                 | 只在 `RuntimeError` 且 `shiboken6.isValid(widget)` 为假时注销；其余异常告警并继续通知其他组件                                                                           |
| libpng 过滤器每装卸一次泄漏一个 fd                  | 备份 stderr 的描述符没有任何一方关闭；`uninstall` 还会在线程读管道时关闭读端；线程退出时丢弃末尾无换行的内容；安装中途失败不释放已开的描述符 | 备份 fd 与管道读端归过滤线程，读到 EOF 后释放；管道写端只以 fd 2 存在，还原 fd 2 即关闭；`uninstall` 限时等待线程；安装失败时关闭已打开的描述符；线程退出前写出末尾内容 |

## 有意保留的差异

| 保留项                          | 原因                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 例外那一类接口继续“摘下归还”    | 它们同时接受字符串与控件，这是有意设计。改成销毁会让原来能放到别处继续使用的控件报“对象已删除”。仓库示例没有依赖这种用法，但库已发布，外部使用情况无法确认 |
| Alert 此前不替换                | 属于缺陷，不保留                                                                                                                                           |
| teardown 不还原字体与已创建组件 | 它们是应用自己的状态，不是库装在应用上的设施                                                                                                               |

## 兼容说明

| 项目     | 说明                                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Alert    | `set_start_content`、`set_end_content` 由“追加”变为“替换”，连续调用不再叠加；接受 `None`。若有代码依赖叠加，需要改为自己管理布局 |
| 广播告警 | 以前被吞掉的组件内部错误，现在会发出 `RuntimeWarning`，每种组合一次                                                              |
| 新增     | `HeroSideUIProvider.teardown()`、`ThemeProvider.release_app_palette()`、`ScrollStyle.peek()`、`fill_slot`                        |
| 公开 API | 其余无变化                                                                                                                       |
