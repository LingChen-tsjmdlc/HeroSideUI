# Window 无边框窗口

自绘标题栏的无边框顶层窗口。HeroUI v2 没有对应组件，这是桌面端专属组件。

主窗口、子窗口、模态窗口都用它。传 `parent` 就是子窗口，不传就是独立顶层窗口。

> 状态：已实现。Windows 11 上做过真实平台的视觉与原生行为自查；Linux、macOS、Windows 10 没有验证（见"已知限制"）。

## 它长什么样

标题栏分三个槽加一组窗口控制按钮，布局由 `system` 决定：

```
windows / linux:  [ 左槽: 图标+标题 ] [ 中槽 ] [ 右槽 ] [ 最小化 最大化 关闭 ]
mac:              [ 关闭 最小化 缩放 ] [ 左槽 ] [ 中槽: 图标+标题 ] [ 右槽 ]
```

- 窗口控制按钮的位置和样式固定跟着 `system` 走，不能放进槽里。
- 三个槽的内容都可以替换。默认内容见下表。

| system  | 左槽默认  | 中槽默认  | 右槽默认 | 控制按钮位置 |
| ------- | --------- | --------- | -------- | ------------ |
| windows | 图标+标题 | 空        | 空       | 最右         |
| linux   | 图标+标题 | 空        | 空       | 最右         |
| mac     | 空        | 图标+标题 | 空       | 最左         |

### 槽的宽度

| 布局            | 固定宽度（按内容） | 弹性宽度（均分剩余空间，1:1） |
| --------------- | ------------------ | ----------------------------- |
| windows / linux | 左槽               | 中槽、右槽                    |
| mac             | 中槽               | 左槽、右槽                    |

槽内的摆放：

- 控件横向是 Expanding（比如搜索框）：撑满整个槽。
- 其余控件按各自内容宽度摆放，靠近窗口控制按钮的一侧对齐：windows / linux 的中槽居中、右槽靠右；mac 的左槽靠左、右槽靠右。
- 槽放不下时，弹性槽先收缩，不会和别的槽重叠。

mac 标题居中修正：红黄绿占了左边一块，如果直接均分，标题会比窗口正中偏右。所以 mac 布局会在右槽右侧预留一块和按钮组等宽的空位，两边对称后，中槽里的标题落在整个窗口的正中间，和真实 macOS 一致。代价是右槽可用宽度少这一块。

### 标题栏高度

参数名是 `title_bar_height`（不叫 `height`：`QWidget` 自带 `height()` 返回窗口高度，同名会覆盖它，Qt 内部也会读错）。单位 px，默认 `None`，按 `system` 取该平台的标准高度：

| system  | 默认高度 | 说明                      |
| ------- | -------- | ------------------------- |
| windows | 32       | Windows 11 标题栏标准高度 |
| mac     | 28       | macOS 普通窗口            |
| linux   | 40       | GNOME 一类，常见 36 到 40 |

传数字就用传入的值，最小 20，更小会被钳到 20。高度变化时，整条标题栏和按钮一起变高：

| 项           | 随高度怎么变                                                |
| ------------ | ----------------------------------------------------------- |
| 标题栏       | 高度 = `title_bar_height`                                   |
| windows 按钮 | 宽度保持 46，高度 = `title_bar_height`                      |
| linux 按钮   | 圆形直径 = `title_bar_height - 16`，最小 16                 |
| mac 圆点     | 直径 = `title_bar_height * 16 / 28` 取整，最小 16，垂直居中 |
| 槽           | 高度 = `title_bar_height`，槽里控件垂直居中                 |

具体比例是初稿，实现时对照真实观感微调。

### 窗口尺寸

窗口自身的宽高用 `width` / `height`，和标题栏高度分开。

| 参数         | 类型          | 默认           | 说明                   |
| ------------ | ------------- | -------------- | ---------------------- |
| `width`      | `int`         | `800`          | 初始窗口宽度，逻辑像素 |
| `height`     | `int`         | `600`          | 初始窗口高度，逻辑像素 |
| `min_width`  | `int \| None` | `None`（保底） | 最小宽度               |
| `min_height` | `int \| None` | `None`（保底） | 最小高度               |
| `max_width`  | `int \| None` | `None`（不限） | 最大宽度               |
| `max_height` | `int \| None` | `None`（不限） | 最大高度               |

- 这几项**不继承**父窗口，子窗口默认也是 800×600。做对话框式的小窗口自己传 `width=400, height=240`。
- 运行时不新增重复接口，直接用 Qt 自带的 `resize()` / `setMinimumSize()` / `setMaximumSize()`，组件在内部叠加保底值。
- **最小尺寸的默认限制**：`min_width` / `min_height` 为 `None` 时，取"固定下限"和"保底值"两者中较大的一个：
  - 固定下限：宽 280、高 160。再小的窗口基本没法用，即使没有任何按钮也不允许。
  - 保底值由组件算出，防止窗口缩到标题栏都放不下：
    - 最小宽度 = 窗口控制按钮组宽度 + 80（windows 约 46×3+80，mac 约 70+80，按显示的按钮数算）。
    - 最小高度 = 标题栏高度 + 40。
  - 传入的 `min_*` 比上面算出的值小，会被抬到该值；比它大就用传入值。保底值随 `system` / 标题栏高度 / 按钮显隐变化而重算。
- **设了最大尺寸后的最大化**：按钮仍然可用，点击时按"工作区"（屏幕扣掉任务栏）和最大尺寸，逐个方向取较小值，再在工作区里居中：

  | 最大尺寸与工作区           | 点最大化的结果                                                 |
  | -------------------------- | -------------------------------------------------------------- |
  | 两个方向都不小于工作区     | 真最大化，铺满工作区                                           |
  | 两个方向都小于工作区       | 窗口钳到最大尺寸，放在工作区正中                               |
  | 一个方向不小于、一个方向小 | 不小于的方向取工作区尺寸，小的方向钳到最大尺寸，放在工作区正中 |

  钳制后的"最大化"叫软最大化：窗口保留圆角和描边，最大化按钮显示"还原"，再点还原回原来的位置和大小；拖动或缩放它，就不再算最大化。没设最大尺寸的方向视为不限。

- **固定尺寸**（`setFixedSize`，最小等于最大）：没有"最大化"的意义，自动隐藏最大化按钮并禁用双击最大化，和 `resizable=False` 一样。mac 的绿色按钮同理整个隐藏。
- 初始尺寸若超出 min/max 范围，会被钳进范围。

## 快速开始

```python
from hero_side_ui import Window, Title, Body

win = Window(system="auto")  # 默认：系统圆角、不透明窗口
win.setWindowTitle("我的应用")
win.setWindowIcon(icon)
win.set_content(Body("窗口内容就是普通 QWidget"))
win.show()

# 想要全平台一致的自绘圆角（beta）：构造时传档位或数字
fancy = Window(radius="md")  # 或 radius=16

# 子窗口：传 parent 即可
child = Window(parent=win)
child.setWindowModality(Qt.WindowModality.WindowModal)
child.show()
```

标题和图标直接用 Qt 自带的 `setWindowTitle` / `setWindowIcon`，默认的"图标+标题"会自动跟着变。

## API

### 构造参数

下表中 `system` 到 `resizable` 七个参数默认都是 `None`，表示"跟随父窗口，没有父窗口时用括号里的最终默认值"，详见下面的"子窗口与配置继承"。窗口尺寸五个参数见上面的"窗口尺寸"，不继承。

| 参数                       | 类型                   | 默认           | 说明                                                                                                                       |
| -------------------------- | ---------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `system`                   | `str \| None`          | `None`（auto） | `auto` / `windows` / `mac` / `linux`                                                                                       |
| `radius`                   | `str \| float \| None` | `"system"`     | 圆角，构造时决定模式，不继承：`"system"` 系统圆角；`None` / `0` 直角；`"sm"/"md"/"lg"` 或数字 = 自绘圆角（beta），见"圆角" |
| `title_bar_height`         | `int \| None`          | `None`         | 标题栏高度 px，`None` 按 `system` 取标准值，最小 20                                                                        |
| `show_minimize`            | `bool \| None`         | `None`（True） | 显示最小化按钮                                                                                                             |
| `show_maximize`            | `bool \| None`         | `None`（True） | 显示最大化/还原按钮（mac 为缩放按钮）                                                                                      |
| `show_close`               | `bool \| None`         | `None`（True） | 显示关闭按钮                                                                                                               |
| `resizable`                | `bool \| None`         | `None`（True） | 能否拖边缘缩放；`False` 时同时隐藏最大化按钮                                                                               |
| `width` / `height`         | `int`                  | `800` / `600`  | 初始窗口尺寸                                                                                                               |
| `min_width` / `min_height` | `int \| None`          | `None`（保底） | 最小尺寸                                                                                                                   |
| `max_width` / `max_height` | `int \| None`          | `None`（不限） | 最大尺寸；最大化时按它钳制并居中，规则见"窗口尺寸"                                                                         |
| `theme`                    | `str`                  | `"auto"`       | `auto` / `light` / `dark`                                                                                                  |
| `parent`                   | `QWidget \| None`      | `None`         | 传了就是子窗口：在父窗口之上，不单独占任务栏                                                                               |

### 公共方法

| 方法                                                                             | 说明                                                                               |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `set_content(w)`                                                                 | 设置内容区，旧内容由窗口销毁                                                       |
| `content_widget()`                                                               | 内容区容器（已带无边距的 `QVBoxLayout`），想自己往里加布局时用                     |
| `set_left(w)` / `set_center(w)` / `set_right(w)`                                 | 替换对应的槽，旧控件由窗口销毁；传 `None` 恢复默认                                 |
| `default_title_widget()`                                                         | 取一个新的"图标+标题"小部件，想保留标题时放进别的槽                                |
| `set_system(s)` / `system()`                                                     | 切换风格；传 `None` 恢复继承；`system()` 返回自己设的值（可能是 `None`）           |
| `resolved_system()`                                                              | 继承和 `auto` 都解析完后的实际风格                                                 |
| `set_radius(r)` / `radius()`                                                     | 圆角；同一模式内可随意切，跨模式（系统 ↔ 自绘）抛 `ValueError`；不继承             |
| `set_title_bar_height(h)` / `title_bar_height()` / `resolved_title_bar_height()` | 标题栏高度；传 `None` 恢复继承                                                     |
| `set_controls(minimize=, maximize=, close=)` / `resolved_controls()`             | 一次设置三个按钮的显隐，没传的保持不变，传 `None` 恢复继承；后者返回生效的三个开关 |
| `set_resizable(v)` / `resizable()` / `resolved_resizable()`                      | 能否缩放；传 `None` 恢复继承                                                       |
| `set_theme(t)`                                                                   | `auto` 跟随全局，或固定 `light` / `dark`                                           |
| `setMinimumSize` / `setMaximumSize` / `setFixedSize` 等                          | Qt 自带方法，Window 在内部叠加默认下限；最大化按最大尺寸钳制，固定尺寸会隐藏最大化 |
| `showMaximized()` / `showNormal()` / `isMaximized()`                             | Qt 自带方法，Windows 上改走系统最大化，状态以系统为准                              |

所有 setter 调用后视觉立即同步，运行时可随意切换。名字带 `resolved_` 的方法返回最终生效的值，不带的返回自己设的值。

setter 取值非法时抛 `ValueError`：`system` / `radius` 不在合法取值里，`title_bar_height` 不是正数（`bool` 也不行），按钮开关和 `resizable` 不是 `bool`。`set_controls` 里"没传"和"传 `None`"是两回事：前者保持不变，后者恢复继承。

### 子窗口与配置继承

每个 Window 都有自己的一份配置，子窗口可以和父窗口完全不同。继承只决定"没设置过时用谁的值"：

1. 构造参数或 setter 给了具体值：用自己的值，不再受父窗口影响。
2. 值是 `None`：向上找最近的 `Window` 祖先，用它生效的值。
3. 找不到 Window 祖先：用最终默认值（`system="auto"`、`title_bar_height` 按系统标准、按钮全开、可缩放）。

继承是动态的：父窗口运行时改了 `system`，没自己设过 `system` 的子窗口会跟着变。

继承的项：`system`、`title_bar_height`、`show_minimize`、`show_maximize`、`show_close`、`resizable`。

不继承的项：

- **三个槽的内容**：一个控件只能有一个父级，没法同时挂在两个窗口里。子窗口的槽默认显示自己的图标和标题。想让子窗口也有同样的内容，需要自己再建一份。
- **`theme`**：沿用全局主题机制，不走继承。

示例：

```python
main = Window(system="windows", title_bar_height=36)
main.show()

a = Window(parent=main)  # 全部跟随 main：windows 风格、36 高
b = Window(parent=main, show_maximize=False)  # 隐藏最大化，其余仍跟随 main
c = Window(parent=main, system="mac")  # 自己是 mac 风格；高度仍跟随 main 的 36

main.set_title_bar_height(30)  # a、b、c 都变成 30
c.set_title_bar_height(40)  # c 独立为 40，不再跟随
c.set_title_bar_height(None)  # c 恢复跟随
```

### 信号

| 信号                      | 说明                                                                        |
| ------------------------- | --------------------------------------------------------------------------- |
| `maximized_changed(bool)` | 最大化状态变化（包括用系统方式最大化，如双击标题栏、Snap Layouts）          |
| `system_changed(str)`     | 解析后的风格变化（windows / mac / linux），自己或父窗口改了 `system` 都会发 |

## 视觉规格

### 三套窗口控制按钮

| 项       | windows              | linux (GNOME 风格)   | mac                               |
| -------- | -------------------- | -------------------- | --------------------------------- |
| 按钮形状 | 46px 宽方块          | 24px 圆形            | 16px 圆点                         |
| 常驻底色 | 无                   | 浅灰圆底             | 红 / 黄 / 绿                      |
| 悬停     | 方块变浅灰，关闭变红 | 圆底加深，关闭不变红 | 整组圆点内显示符号                |
| 按钮间距 | 紧贴                 | 约 6px               | 8px                               |
| 图标     | 16px SVG，随栏高不变 | 约按钮直径的 60%     | 约圆点直径的 80%，黑色 60% 透明度 |
| 默认栏高 | 32                   | 40                   | 28                                |

按钮的底色、圆点、悬停态是自绘的，里面的符号统一用内置的 Fluent SVG 图标（随包离线提供，不依赖系统字体），按主题和按钮状态着色，高分屏下按设备像素比渲染。

| 用途                     | 图标                                                     |
| ------------------------ | -------------------------------------------------------- |
| 关闭                     | `fluent--dismiss-24-filled`                              |
| 最小化                   | `fluent--subtract-24-filled`                             |
| 最大化                   | `fluent--maximize-24-filled`                             |
| 还原                     | `fluent--square-multiple-24-regular`                     |
| mac 进入全屏（绿色按钮） | `fluent--arrow-maximize-top-left-bottom-right-24-filled` |
| mac 退出全屏             | `fluent--arrow-minimize-top-left-bottom-right-24-filled` |

mac 按住 Alt 悬停时，绿色按钮改画最大化 / 还原图标，对应 Alt+点击的行为。按钮尺寸随 `title_bar_height` 变化，规则见"标题栏高度"。

### mac 按钮的行为

| 按钮 | 点击     | Alt+点击    |
| ---- | -------- | ----------- |
| 红   | 关闭     | 关闭        |
| 黄   | 最小化   | 最小化      |
| 绿   | 切换全屏 | 最大化/还原 |

- 绿色按钮默认是全屏，和真实 macOS 一致。
- 全屏时标题栏保持显示，不做"顶部隐藏、鼠标移上去才出现"。
- `show_maximize=False` 隐藏整个绿色按钮。
- 按钮从左到右的顺序按 macOS 原样：关闭、最小化、缩放。

### 窗口行为

| 行为           | 说明                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 拖动           | 标题栏空白处按下即拖动，交给系统接管，Windows 上贴边吸附可用；规则见"标题栏拖动与交互控件" |
| 缩放           | 边缘约 6px 为缩放热区，光标随位置变化                                                      |
| 双击标题栏     | 最大化/还原；`show_maximize=False`、不可缩放或固定尺寸时不响应                             |
| 最大化或全屏时 | 圆角归零，缩放热区关闭，最大化按钮换成还原图标（软最大化保留圆角，见"窗口尺寸"）           |
| 关闭按钮       | 调用 `close()`，正常走 `closeEvent`                                                        |
| 子窗口         | 在父窗口之上，不单独占任务栏，随父窗口一起关闭；关闭它不会退出程序                         |
| 模态           | 用 Qt 的 `setWindowModality`                                                               |
| 配置           | 每个窗口独立，默认继承父窗口，见"子窗口与配置继承"                                         |

### 圆角

`radius` 的取值：

| 取值                             | 含义                                     | 模式             |
| -------------------------------- | ---------------------------------------- | ---------------- |
| `"system"`（默认）               | 系统圆角：Windows 11 有，Windows 10 直角 | 系统模式         |
| `None` 或 `0`                    | 直角                                     | 系统模式         |
| `"sm"` / `"md"` / `"lg"`         | 6 / 10 / 14 px                           | 自绘圆角（beta） |
| 大于 0 的数字（`int` / `float`） | 就是那么多像素                           | 自绘圆角（beta） |

`bool`、负数、`NaN`、`inf`、其它字符串抛 `ValueError`。数值不取主题 `RADIUS`（窗口圆角和组件圆角是两回事）。自绘圆角最大化或全屏时归零；数字过大时按窗口短边的一半自动压缩。

自绘的圆角是**超椭圆**（苹果的连续圆角）：弧线从直边上更远处开始缓缓弯曲，不会在弧线和直边的交界处有"角"的感觉。数值是基准半径，实际弧线在边上占约 1.6 倍长度。平滑度由 `WINDOW_SPEC["corner_smoothing"]` 控制（0 是普通圆角，默认 0.6 接近 iOS，最大 1），窗口很小时会自动压缩，不会让两个角的弧线相撞。

### 颜色

跟随主题，暗色下按索引镜像取色（`HEROUI_COLORS` 恒为亮色原始值）。

| 项               | 亮色                                | 暗色              |
| ---------------- | ----------------------------------- | ----------------- |
| 窗口背景         | 主题 `background`                   | 主题 `background` |
| 标题栏底色       | default-100                         | default-800       |
| 外框描边（1px）  | default-200                         | default-700       |
| 图标 / 文字      | 主题 `foreground`                   | 主题 `foreground` |
| 按钮悬停 / 按下  | 前景色 10% / 16%                    | 前景色 10% / 16%  |
| windows 关闭悬停 | `#e81123`，按下 `#f1707a`，图标变白 | 同左              |
| mac 红 / 黄 / 绿 | `#ff5f57` / `#febc2e` / `#28c840`   | 同左              |
| mac 失焦圆点     | `#cdcdcd`                           | `#5a5a5a`         |

`theme="auto"` 的窗口跟随全局主题；`theme="light"` / `"dark"` 的窗口固定，不受全局切换影响。窗口里的其他组件各自有自己的 `theme`，窗口不会替它们改。

### 标题栏拖动与交互控件

标题栏空白处和槽里的纯展示控件（比如默认的标题文字）可以拖动窗口。槽里放了可交互的控件时，在它上面点击属于控件自己，不会拖动窗口。判断规则：

- 按钮、能获得焦点的控件（输入框、可选中文字的标签等）：不拖动。
- 带 `heroWindowNoDrag` 属性的控件：不拖动。自己写的、会处理鼠标点击但没有焦点的控件用它标记：`w.setProperty("heroWindowNoDrag", True)`。
- 其余：可拖动。

## 技术路线

Window 有**两种模式**，由构造时的 `radius` 决定，运行中不能互相切换（会抛 `ValueError`）。

|              | 系统模式（默认）                                                       | 自绘圆角模式（beta）                                      |
| ------------ | ---------------------------------------------------------------------- | --------------------------------------------------------- |
| 触发         | `radius="system"`（默认）、`None`、`0`                                 | `radius="sm"/"md"/"lg"` 或大于 0 的数字                   |
| 窗口         | 不透明无边框窗口，标题栏、槽、按钮仍是自绘                             | 透明无边框窗口，圆角背景、描边都自己画                    |
| 圆角         | `"system"`：Windows 11 由系统画（Windows 10 直角）；`None` / `0`：直角 | 超椭圆，全平台一致，数值可调                              |
| 阴影         | 系统自带（直角窗口会补开）                                             | 开启 DWM 阴影，见下                                       |
| 缩放闪烁     | 无（不透明窗口不走分层窗口路径）                                       | 靠 D3D11 缓解，见"已知限制"                               |
| 进程级副作用 | 无                                                                     | Windows 上设置 `QT_WIDGETS_RHI`，之后所有顶层窗口走 D3D11 |

自绘圆角模式是 beta：它要靠透明窗口，Windows 上缩放有闪烁风险，要靠 D3D11 压住，所以默认走系统模式，只有明确要全平台一致圆角的人才承担这些代价。

实验在 Windows 11（build 26200）、PySide6 6.11.0 上做，缩放比例 1.0 / 1.5 / 2.0。

### 实验结果

| 问题                                 | 结论                                                                                                                                                                                                                                                                        |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 内容区的角被子控件盖住，怎么保持圆角 | 可行。顶层放一个透明覆盖层，用 `Clear` 合成模式擦掉圆角外区域，再画 1px 描边                                                                                                                                                                                                |
| 覆盖层稳定吗                         | 稳定。子控件换色、连续重绘 20 次、窗口缩放后四角都没有悬出的方角；三种缩放比例下弧线都平滑                                                                                                                                                                                  |
| `setMask` 兜底                       | 能裁出圆角，但边缘是阶梯锯齿，没有描边。不采用                                                                                                                                                                                                                              |
| 缩放性能                             | 透明+覆盖层比不透明慢约 10%（全屏 69ms vs 63ms，内容是 400 个按钮），瓶颈在内容重绘，不在透明                                                                                                                                                                               |
| 外圈投影                             | 默认**没有**（窗口外一圈像素全是垫底色）。在 Windows 上把 DWM 非客户区渲染"先关再开"并扩展 1px 边框后，系统会画柔和阴影，实测窗口外约 58px 渐变变暗；最大化时系统自动不画。最大化 / 还原、最小化 / 还原、隐藏再显示后阴影会丢，所以每次状态变化后重做（见 `enable_shadow`） |
| 最大化按钮能否触发 Snap Layouts      | 实验里补上 `WS_CAPTION \| WS_THICKFRAME \| WS_MAXIMIZEBOX` 并返回 `HTMAXBUTTON` 后，按钮下方出现了弹层区域的像素变化；只返回 `HTMAXBUTTON` 没有变化。组件里的实际弹层需要真人悬停确认                                                                                       |
| 最小化动画                           | 实验里加上述样式后恢复；不加则窗口直接消失                                                                                                                                                                                                                                  |
| 最大化后的窗口矩形                   | 比工作区每边大约 8px（见下）。组件里已按实测量把内容缩进，屏幕上四角像素都是窗口自己的颜色                                                                                                                                                                                  |

### Windows 上的做法

非 Windows 平台走 Qt 自带的 `startSystemMove` / `startSystemResize`，缩放热区是 8 个贴边的小控件。Windows 上走原生消息，才能拿到 Snap Layouts、贴边吸附和最小化动画。只在 Windows 平台插件下启用（`offscreen` 等不启用）。强制 `system="mac"` 在 Windows 上显示 mac 布局时，用的仍是这套原生行为，只有外观和按钮位置不同。

| 消息 / 调用                | 做什么                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 补窗口样式                 | 窗口显示后加 `WS_CAPTION \| WS_THICKFRAME \| WS_MINIMIZEBOX \| WS_MAXIMIZEBOX`，每次显示、状态变化后都检查补齐 |
| `WM_NCCALCSIZE`            | 返回 0，客户区占满整个窗口，等于吃掉系统标题栏和边框                                                           |
| `WM_GETMINMAXINFO`         | 填最小 / 最大尺寸，最大化范围 = 工作区与最大尺寸逐方向取小并居中（系统发起的最大化也遵守）                     |
| `WM_NCHITTEST`             | 边缘返回 `HTLEFT` 等，标题栏空白返回 `HTCAPTION`，最大化按钮返回 `HTMAXBUTTON`，其余返回 `HTCLIENT`            |
| `WM_NCMOUSEMOVE` / `LEAVE` | 最大化按钮在非客户区，没有 Qt 鼠标事件，悬停态由这两个消息驱动                                                 |
| `WM_NCLBUTTONDOWN` / `UP`  | 最大化按钮自己接管点击；`NCLBUTTONUP` 里延后一拍再切换最大化                                                   |
| `WM_NCLBUTTONDBLCLK`       | 不交给系统（系统会直接最大化，绕过最大尺寸的钳制），由窗口自己切换最大化 / 还原                                |
| 最大化 / 还原              | 用 `ShowWindow(SW_MAXIMIZE / SW_RESTORE)`，状态读 `IsZoomed`                                                   |

只有 `system` 解析为 windows 或 linux 布局、且运行在 Windows 上时，才对最大化按钮返回 `HTMAXBUTTON`。mac 布局的绿色按钮不触发 Snap Layouts。

**最大化的 8px 溢出**：系统最大化 `WS_THICKFRAME` 窗口时，窗口矩形每边会比工作区大约 8px（这个量会随 DPI 变），而透明窗口的位图是按窗口矩形贴的，内容会整体偏移。试过的办法：在 `WM_NCCALCSIZE` 里收边框（没用，位图位置不变）、在 `WM_GETMINMAXINFO` 里设最大化范围（系统仍会加回去）、跳过 Qt 对 `WM_WINDOWPOSCHANGING` 的处理（没用）、事后 `SetWindowPos` 设回工作区（系统每次都再加回去）。最后的做法：承认矩形会溢出，最大化时用实测的溢出量把根布局的边距加大，内容刚好落在工作区；溢出的那圈不绘制、保持透明。

### 已知限制

- **自绘圆角模式的缩放闪烁与 D3D11**：透明窗口默认走"分层窗口"路径，缩放时系统要等整张位图提交完才更新画面，所以帧率低还会漏画：真机日志里系统改尺寸次数只有不透明窗口的 1/7，约 4 成步骤来不及重绘，缩放时就出现整窗内容缩进、标题栏和圆角消失的单帧闪烁。试过缩放时同步重绘（更差）、`WVR_REDRAW`（无效）、不透明窗口加系统圆角（不闪，但 Win10 无圆角、Win11 只有 4px / 8px 两档，达不到全平台一致）、`SetWindowRgn` 和 DWM 玻璃（不闪，但圆角不可调）。最后用 `QT_WIDGETS_RHI=1` + `QT_WIDGETS_RHI_BACKEND=d3d11` 让 Qt 改用 D3D11 提交：不闪，圆角仍是自绘、可调。
  - 只有自绘圆角窗口在 Windows 上创建时才会设置这两个变量（你已经设过就不动）；系统模式完全不碰。
  - 这是进程级设置，之后创建的所有顶层窗口（弹层等）也走 D3D11。Qt 只在第一个顶层窗口显示时读一次，所以自绘圆角窗口要在应用里最早的窗口显示之前创建，否则不生效（缩放会闪，但不会黑屏）。
  - `QT_WIDGETS_RHI` 是 Qt 的内部开关，官方文档没有，以后版本可能改变行为。
  - D3D11 创建失败时 Qt 只打一行日志，窗口会黑屏（实测）。所以设变量前先自己试创建一次 D3D11 硬件设备，失败就不设，窗口走默认路径（缩放可能闪，但能显示）。设 `HSUI_WINDOW_RHI=0` 可以直接关闭。
  - 没有 D3D11 硬件设备时的探测失败路径只验证了逻辑，没在真实环境跑过。
- 没验证的：Windows 10 上自绘圆角模式和 D3D11 的表现；虚拟机、远程桌面等没有 D3D11 硬件设备的环境只验证了"探测失败走默认路径"这一逻辑，没在真实环境上跑。
- **系统模式在 macOS / Linux 上什么都不设**：窗口长什么样由平台和窗口管理器决定，圆角、阴影是否存在没有验证。Windows 11 实测有系统圆角和阴影。

- 窗口右下角约 3×3 像素范围内按下，系统缩放不会启动（其余三个角没有这个问题；缩放热区 6px，所以右下角仍有 3 到 5px 能用）。原因没查清。
- 最大化时 `geometry()` 比屏幕每边大约 8px（窗口矩形的溢出，见上）。要拿屏幕上可见的区域，读内容区或标题栏的全局坐标。
- 最大化按钮的悬停色靠消息驱动，实测过逻辑，没有真人悬停验证过视觉。
- 阴影是 Windows 系统画的，只有 Windows 上有；其它平台没有外圈阴影。阴影形状由系统决定，不能调颜色和范围。没验证 Windows 10 上的阴影，也没有验证系统关闭了"窗口阴影"选项时的表现。
- 内容里放原生渲染控件（OpenGL、WebView）时，覆盖层擦不掉它们盖住的圆角。
- 任务栏自动隐藏时，最大化窗口会盖住它（没做 1px 让位）。
- 没验证的：Windows 10 上的表现；Linux、macOS 上的实际表现（缩放热区、`startSystemMove`、全屏）；Snap Layouts 弹层的真实外观；从最大化状态拖动标题栏还原。

### 确定不做的

- 自绘外圈投影（窗口外留透明边距）：Windows 上用系统阴影，其它平台暂不做。
- 最小化 / 最大化的自绘动画：Windows 上用系统自带的。
- Mac 全屏时标题栏自动隐藏（鼠标移到顶部才出现）。

## 设计说明

- **样式决策在组件内部**：不同 `system` 的尺寸、颜色、图标全由 Window 自己决定，使用方不需要写 `if system`。
- **槽的内容归使用方管**：`set_left` 等只持有，不改变其样式；传 `None` 恢复默认。
- **`system` 不影响功能**：强制 `mac` 只改外观和按钮位置，拖动、缩放、关闭的行为在所有平台一致，绿色按钮的全屏/最大化除外。
- **不是 Dialog**：Window 是通用窗口外壳。带结果码、确认/取消按钮的对话框是 [Dialog](dialog.md)，它建在 Window 之上，不混在一起。

## 与 HeroUI 的关系

HeroUI v2 没有窗口组件，这是桌面端专属组件。参考的是各平台真实窗口的外观：Windows 11、GNOME Adwaita、macOS。
