# Dialog 对话框

桌面端的模态对话框：一个带结果码的子 Window。用来提示、确认、让用户填一点东西，关闭之前用户不能操作主窗口。HeroUI v2 没有对应组件（它的 Modal 是网页里叠在页面上的一层，桌面端不适用），这是桌面端专属组件。

> 状态：已实现。Windows 11 上做过真实平台的截图自查（亮 / 暗主题、五种图标、压暗与模糊遮罩、九宫格位置、mac 风格、固定高度、自动高度与内部滚动）；Linux、macOS 没有验证。

## 它长什么样

外观就是 Window，不另画一套。圆角、阴影、标题栏、`system` 风格、`theme` 全部来自 Window。

```
┌────────────────────────────────┐
│ 标题                          ✕│  Window 标题栏，默认只留关闭按钮
├────────────────────────────────┤
│  (i)   小标题（次要色）        │  body：图标 + 小标题 + 正文
│        正文（主色）            │  可以整个换成任意 QWidget
│                   [取消] [确定]│  footer：按钮区，可以为空
└────────────────────────────────┘
```

和 Window 相比，Dialog 多了三样东西：

| 多出来的       | 说明                                                                  |
| -------------- | --------------------------------------------------------------------- |
| 结果码         | `exec()` 阻塞等待并返回整数结果码；按钮可以自定义结果码，还能附带数据 |
| 默认行为       | 模态、固定尺寸、居中、只有关闭按钮                                    |
| 现成的内容布局 | 图标 + 小标题 + 正文 + 按钮区，不想用可以整个替换                     |

## 快速开始

```python
from hero_side_ui import Dialog, Button

# 一行确认：点"确定"返回 True，其它方式关闭返回 False
if Dialog.confirm(win, "删除文件", "删除后无法恢复，继续吗？", icon="warning", color="danger"):
    delete()

# 自己搭
dlg = Dialog(title="重命名", heading="文件名", message="请输入新的名称", parent=win)
dlg.set_footer([("取消", "reject"), ("确定", "accept")])
if dlg.exec() == Dialog.Accepted:
    ...

# 自定义结果码：加一个"跳过"按钮，结果码 -1
SKIP = -1
dlg.set_footer([("跳过", SKIP), ("取消", "reject"), ("确定", "accept")])
code = dlg.exec()  # 1 确定 / 0 取消 / -1 跳过

# 不阻塞：打开后靠信号
dlg.finished.connect(lambda code: ...)  # 任何结果码都会发
dlg.accepted.connect(on_ok)  # 仅结果码为 1
dlg.open()
```

结果码与结果数据的完整规则见"按钮与结果码"和"行为说明"。

## API

### 构造参数

内容：

| 参数                 | 类型                     | 默认     | 说明                                                                                        |
| -------------------- | ------------------------ | -------- | ------------------------------------------------------------------------------------------- |
| `title`              | `str`                    | `""`     | 标题栏文字                                                                                  |
| `heading`            | `str \| None`            | `None`   | body 里的小标题（次要色）                                                                   |
| `message`            | `str \| None`            | `None`   | body 里的正文；`heading` 和 `message` 都不传则 body 为空，自己 `set_body`                   |
| `icon`               | `str \| QWidget \| None` | `"info"` | `info` / `success` / `warning` / `danger` / `question`，`None` 不显示，也可传自己的 QWidget |
| `color`              | `str \| None`            | 跟随图标 | 图标和主按钮的语义色，可单独覆盖                                                            |
| `icon_size`          | `int`                    | `32`     | 图标边长 px                                                                                 |
| `message_selectable` | `bool`                   | `True`   | 正文能否选中复制                                                                            |

图标与默认颜色：

| `icon`     | 默认色  | 图标                                     |
| ---------- | ------- | ---------------------------------------- |
| `info`     | primary | `heroicons--information-circle-solid`    |
| `success`  | success | `heroicons--check-solid`，外面画一个圆底 |
| `warning`  | warning | `heroicons--exclamation-triangle-solid`  |
| `danger`   | danger  | `heroicons--x-circle-solid`              |
| `question` | primary | `material-symbols--help-outline`         |

尺寸：宽度固定，高度默认跟着内容走。

| 参数                       | 默认                     | 说明                                                  |
| -------------------------- | ------------------------ | ----------------------------------------------------- |
| `width`                    | `420`                    | 固定宽度，文字在这个宽度下自动换行                    |
| `height`                   | `None`（自动）           | `None` 按内容算高；传数字就固定为该高度，不再跟内容变 |
| `min_width` / `min_height` | `None`（保底）           | 沿用 Window 的最小尺寸规则（宽 280、高 160）          |
| `max_width` / `max_height` | `None`（宽不限；高见下） | 最大尺寸                                              |
| `resizable`                | `False`                  | 能否拖边缘缩放                                        |

详见"自动高度"。

位置与模态：

| 参数               | 默认       | 说明                                                                                |
| ------------------ | ---------- | ----------------------------------------------------------------------------------- |
| `placement`        | `"center"` | 九宫格，相对父窗口；没有父窗口则相对屏幕。见下表                                    |
| `placement_offset` | `(0, 0)`   | 在九宫格位置上再偏移的 px，最终位置会被钳回屏幕内                                   |
| `modality`         | `"window"` | `window` 只挡住父窗口；`application` 挡住整个程序；`none` 不挡                      |
| `backdrop`         | `"none"`   | 对父窗口的处理：`none` 无效果 / `dim` 压暗 / `blur` 模糊；没有父窗口时按 `none`     |
| `stay_on_top`      | `"system"` | 置顶方式：`none` 不置顶 / `parent` 只压在父窗口之上 / `system` 系统级置顶，见"置顶" |

`placement` 的九个取值：

```
| ------------------ | ------------- | ------------------- |
| 左上 `top-left`    | 中上 `top`    | 右上 `top-right`    |
| ------------------ | ------------- | ------------------- |
| 左 `left`          | 中 `center`   | 右 `right`          |
| ------------------ | ------------- | ------------------- |
| 左下 `bottom-left` | 中下 `bottom` | 右下 `bottom-right` |
| ------------------ | ------------- | ------------------- |
```

按钮与键盘：

| 参数                | 默认     | 说明                                                                                                                                                                          |
| ------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `footer_align`      | `"end"`  | `start` / `center` / `end` / `stretch`（按钮均分撑满）                                                                                                                        |
| `button_order`      | `"auto"` | `auto` 等于 `cancel_first`：取消在前、确定在后（确定在右），所有风格一致；想把确定放前面传 `ok_first`。只有 `accept` 角色的按钮会被移到最后（或最前），其余按钮保持你写的顺序 |
| `dismiss_on_escape` | `False`  | 按 Esc 是否等于取消。默认不允许，避免误触丢掉用户正在填的内容                                                                                                                 |

标题栏和外壳（沿用 Window）：

| 参数                                                          | 默认      | 说明                               |
| ------------------------------------------------------------- | --------- | ---------------------------------- |
| `show_minimize`                                               | `False`   | 模态对话框最小化没有意义，默认隐藏 |
| `show_maximize`                                               | `False`   | 同上                               |
| `show_close`                                                  | `True`    | 关闭按钮；关闭视为取消             |
| `system` / `radius` / `theme` / `title_bar_height` / `parent` | 同 Window |                                    |

### 按钮与结果码

`set_footer` 接收按钮列表。每个按钮的"角色"决定点击后关闭对话框时的结果码，开发者可以给任意按钮指定自己的结果码，比如加一个"跳过"按钮，结果码定为 `-1`。

列表里每一项可以这样写：

| 写法                                      | 说明                             |
| ----------------------------------------- | -------------------------------- |
| `Button`                                  | 角色为 `none`                    |
| `(文字, 角色)`                            | 简写，Dialog 自己创建按钮        |
| `(文字, 角色, 数据)`                      | 同上，并在点击时附带一份结果数据 |
| `(Button, 角色)` / `(Button, 角色, 数据)` | 用你自己创建的 `Button`          |

角色决定点击后发生什么：

| 角色               | 点击后                       | 结果码 |
| ------------------ | ---------------------------- | ------ |
| `accept`           | 关闭，视为接受               | `1`    |
| `reject`           | 关闭，视为拒绝               | `0`    |
| 任意整数（自定义） | 关闭，结果码就是这个整数     | 该整数 |
| `none`             | 只发出按钮自己的信号，不关闭 | 不变   |

自定义结果码的规则：

- 可以是任意整数，包括负数。`accept` 和 `reject` 只是 `1` 和 `0` 的别名，所以 `("确定", 1)` 与 `("确定", "accept")` 完全等价。
- `bool` 不能当结果码（`True` 会和 `1` 混淆），传了抛 `ValueError`；不认识的字符串角色同样抛 `ValueError`。
- 建议在自己的代码里给自定义码起名，不要到处写魔法数字。

```python
SKIP = -1  # 自己定义的结果码

dlg = Dialog(title="导入", message="发现同名文件，怎么处理？", icon="warning", parent=win)
dlg.set_footer([("跳过", SKIP), ("取消", "reject"), ("覆盖", "accept")])

code = dlg.exec()
if code == Dialog.Accepted:
    overwrite()
elif code == SKIP:
    skip()
else:  # Dialog.Rejected
    abort()
```

只想加一个按钮时用 `add_button(button, role="none", data=None)`，返回这个按钮。

Enter 触发默认按钮：`set_default_button()` 指定的按钮；没指定就取第一个 `reject` 角色的按钮。

### 公共方法

| 方法                                                                                             | 说明                                                     |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `exec() -> int`                                                                                  | 打开并阻塞，直到关闭，返回结果码                         |
| `open()`                                                                                         | 打开，不阻塞，靠信号拿结果                               |
| `accept()` / `reject()`                                                                          | 以结果码 `1` / `0` 关闭                                  |
| `done(code, data=None)`                                                                          | 以任意整数结果码关闭，可附带结果数据                     |
| `result() -> int`                                                                                | 读结果码，关闭前为 `0`                                   |
| `result_data()` / `set_result_data(obj)`                                                         | 读 / 写结果数据（任意 Python 对象，默认 `None`）         |
| `set_result_data_provider(fn)`                                                                   | 关闭时才取数据，见"结果码与结果数据"                     |
| `set_body(w)` / `body_widget()`                                                                  | 替换 / 取得内容区                                        |
| `set_footer(buttons)` / `add_button(b, role, data)` / `set_default_button(b)`                    | 设置按钮区 / 追加一个按钮 / 默认按钮                     |
| `buttons()`                                                                                      | 按钮区的全部按钮（创建顺序）                             |
| `set_title` `set_heading` `set_message` `set_icon` `set_color`                                   | 内容类 setter                                            |
| `set_icon_size` `set_message_selectable` `set_theme`                                             | 图标大小 / 正文可选中 / 主题                             |
| `icon()` `color()` `placement()` `modality()` `backdrop()` `stay_on_top()` `dismiss_on_escape()` | 读回当前设置                                             |
| `set_placement` `set_placement_offset` `set_modality` `set_backdrop` `set_stay_on_top`           | 位置与模态类 setter                                      |
| `set_footer_align` `set_button_order` `set_dismiss_on_escape`                                    | 按钮与键盘类 setter                                      |
| `set_height(h \| None)`                                                                          | 固定高度 / 恢复自动高度                                  |
| `Dialog.alert(parent, title, message, ...)`                                                      | 只有"确定"的提示                                         |
| `Dialog.confirm(parent, title, message, ...)`                                                    | 确认 / 取消，点确认返回 `True`，其它关闭方式返回 `False` |
| `Dialog.choose(parent, title, message, buttons, ...)`                                            | 自定义按钮的一行调用，返回被点按钮的结果码               |

所有 setter 调用后视觉立即同步。`alert` / `confirm` 用的就是上面这套参数搭出来的预设（图标、文案、颜色、按钮文字都能传），布局固定为"图标 + 文案 + 右下按钮"；想要别的样子，用 Dialog 自己搭。

三个一行调用都是阻塞的，关闭后对话框随即销毁。只有"确定"的 `alert` 会把 Enter 绑给这个按钮（没有取消按钮可兜底）；`confirm` / `choose` 按通用规则，Enter 触发第一个 `reject` 角色的按钮。图标默认值：`alert` / `choose` 是 `info`，`confirm` 是 `question`。

### 信号

| 信号            | 什么时候发                     | 说明                       |
| --------------- | ------------------------------ | -------------------------- |
| `finished(int)` | 每次关闭都发，无论结果码是多少 | 参数是结果码；自定义码靠它 |
| `accepted()`    | 仅结果码为 `1`                 | 无参数                     |
| `rejected()`    | 仅结果码为 `0`                 | 无参数                     |

- 结果码为 `-1`、`10` 这类自定义值时，只发 `finished(code)`，`accepted` / `rejected` 都不发。想处理自定义码，连 `finished` 再判断。
- 同一次关闭内的顺序：先 `finished(code)`，再 `accepted()` 或 `rejected()`（和 Qt 一致）。`exec()` 在信号都发完之后才返回。
- 结果数据在信号发出之前就已经就位，槽函数里可以直接 `dlg.result_data()`。

结果码常量：`Dialog.Rejected = 0`，`Dialog.Accepted = 1`。其余整数都可以自己定义。

## 行为说明

### 结果码从哪来

每次对话框关闭，都有且只有一个结果码。它的来源：

| 谁触发关闭                             | 结果码 |
| -------------------------------------- | ------ |
| 点 `accept` 角色的按钮 / 调 `accept()` | `1`    |
| 点 `reject` 角色的按钮 / 调 `reject()` | `0`    |
| 点自定义整数角色的按钮 / 调 `done(n)`  | `n`    |
| 点标题栏的关闭按钮                     | `0`    |
| 按 Esc（`dismiss_on_escape=True` 时）  | `0`    |
| 代码调用 `close()`                     | `0`    |

标题栏关闭按钮、Esc、`close()` 这三条"非按钮"的关闭路径固定是 `0`（取消）。想把"跳过"和"取消"区分开，就让"跳过"是一个有自己结果码的按钮，用户点的是它，而不是关窗。

`show_close=False` 且 `dismiss_on_escape=False` 时，界面上只剩 footer 里的按钮能关闭它，这是想强制用户做选择时用的。系统层面的关闭（Alt+F4、任务栏右键关闭）不拦截，仍按取消处理，结果码 `0`。

代码里调用 `hide()` 同样按取消处理；窗口被系统最小化这类自发隐藏不算。

### 结果码的生命周期

| 时刻                            | 行为                                                                      |
| ------------------------------- | ------------------------------------------------------------------------- |
| 每次 `open()` / `exec()` 开始   | 结果码重置为 `0`，结果数据重置为 `None`，所以同一个对话框对象可以反复打开 |
| 打开期间                        | `result()` 恒为 `0`，结果在关闭那一刻才确定                               |
| 关闭之后                        | `result()` 保持最后一次的结果码，直到下次打开                             |
| 已关闭 / 未打开时调 `done()`    | 忽略，不发任何信号（避免重复发信号）                                      |
| 同一次打开里连续调两次 `done()` | 第一次生效，第二次忽略                                                    |

### 结果数据 result_data

整数结果码只能表达"点了哪个按钮"。需要带回内容（比如用户输入的文字）时，用结果数据：任意 Python 对象，默认 `None`。

设置的方式：

| 方式                                    | 适合场景                                              |
| --------------------------------------- | ----------------------------------------------------- |
| 按钮的第三项：`("确定", "accept", obj)` | 不同按钮带不同的固定数据                              |
| `done(code, data)`                      | 代码里主动关闭时带上数据                              |
| `set_result_data(obj)`                  | 关闭之前随时写入                                      |
| `set_result_data_provider(fn)`          | 关闭那一刻才取：`fn()` 的返回值作为数据，适合读输入框 |

规则：

- `done(code, data)` 或按钮第三项给出的数据（不为 `None`）会覆盖之前 `set_result_data` 写入的值。
- `provider` 只在数据仍是 `None` 时才调用，且结果码为 `0`（取消）时不调用，取消不需要带回输入。
- 数据在 `finished` / `accepted` / `rejected` 信号发出之前就已就位。

```python
edit = Input(placeholder="新名称")
dlg = Dialog(title="重命名", parent=win)
dlg.set_body(edit)
dlg.set_result_data_provider(lambda: edit.text())
dlg.set_footer([("取消", "reject"), ("确定", "accept")])

if dlg.exec() == Dialog.Accepted:
    rename(dlg.result_data())
```

### Dialog.choose：自定义按钮的一行调用

`alert` 只有"确定"，`confirm` 返回对错，要多个自定义按钮时用 `choose`，直接返回被点按钮的结果码：

```python
SKIP = -1
code = Dialog.choose(
    win, "导入", "发现同名文件，怎么处理？",
    buttons=[("跳过", SKIP), ("取消", "reject"), ("覆盖", "accept")],
    icon="warning",
)
```

关闭窗口、按 Esc 返回 `0`。`buttons` 的写法与 `set_footer` 完全一致。

### exec() 怎么阻塞

`exec()` 内部自带一个本地事件循环，对话框关闭时退出循环，行为和 Qt 的 `QDialog.exec()` 一致，可以在任意位置阻塞调用并拿到返回值。父窗口在阻塞期间被关闭、或应用要退出时，循环会随之退出，不会卡死。

### 阻塞时点主窗口会"叮"一声吗

会，而且是系统自带的，Dialog 不需要另做。

Windows 对模态对话框的处理是：Qt 把被挡住的父窗口设为"禁用"，之后点它的任何位置，系统都在把消息送给窗口之前就拦下，并闪烁对话框的标题栏、响提示音。Window 接管的 `WM_NCHITTEST` 等消息也收不到，所以不会干扰这套反馈。

在 Windows 11 真机上用真实鼠标注入实测过（`SendInput`），用 Qt 原生窗口做对照，子窗口设为 `WindowModal`：

| 操作                 | Qt 原生窗口                 | Window                      |
| -------------------- | --------------------------- | --------------------------- |
| 点父窗口内容区       | 对话框闪烁 9 次，父窗口不动 | 对话框闪烁 9 次，父窗口不动 |
| 点父窗口标题栏       | 闪烁 12 次，不动            | 闪烁 12 次，不动            |
| 拖父窗口标题栏       | 闪烁 14 次，位置不变        | 闪烁 14 次，位置不变        |
| 双击父窗口标题栏     | 闪烁 15 次，不最大化        | 闪烁 15 次，不最大化        |
| 点对话框自己（对照） | 正常激活                    | 正常激活                    |

两边逐项一致：父窗口收不到任何点击，标题栏拖不动、双击不最大化。"闪烁次数"是对话框收到的 `WM_NCACTIVATE` 来回切换的次数。

没有测到的：提示音本身。测试机器正在播放音频，没法从音频电平里分辨出一声短促的提示音。"叮"和闪烁来自系统的同一条处理路径，Window 的闪烁序列与原生完全相同，所以认为提示音也一致，但没有直接量到。`modality="application"` 也没有单独测。

### 自动高度

`height=None`（默认）时，对话框高度 = 标题栏 + body 内容 + footer，随内容自动撑开：

| 情况              | 结果                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------- |
| 内容很少          | 不小于最小高度 160                                                                        |
| 内容正常          | 刚好放下内容                                                                              |
| 内容超过上限      | 窗口停在上限，body 内部出现滚动，标题栏和 footer 始终可见                                 |
| 传了 `height`     | 固定为传入值（仍受 `min_*` / `max_*` 限制），不再跟内容变；内容放不下时 body 同样内部滚动 |
| 传了 `max_height` | 上限以它为准                                                                              |
| 没传 `max_height` | 上限 = 屏幕可用高度（扣掉任务栏）的 80%                                                   |

- **宽度固定**：只撑高度。文字在 `width` 下换行，所以长文案会变高而不会变宽。
- **打开后内容变了也会重算**：改 `heading` / `message` / `icon` / `set_body` / `set_footer` 之后，只要没传过固定 `height`，窗口会重新算高度。
- **变高时位置不跳**：以 `placement` 对应的锚点为基准，`top*` 顶边不动，`bottom*` 底边不动，其余垂直居中，最后钳回屏幕内。
- **body 自己带滚动**：超出上限时 Dialog 自己给 body 套滚动区，使用方不需要手动放 `ScrollShadow`；放了也不冲突。
- `set_height(h)`：运行时改成固定高度；传 `None` 恢复自动。

### 置顶

`stay_on_top` 决定对话框在窗口层级里站哪：

| 取值     | 效果                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| `none`   | 不置顶，对话框是父窗口的从属窗口：始终压在父窗口之上，切到别的程序时跟着退到后面 |
| `parent` | 同 `none`（见下）                                                                |
| `system` | 系统级置顶（默认）：盖在所有程序的窗口之上，切到别的程序也一直在最前面           |

- **`none` 与 `parent` 效果一样**：有父窗口的对话框，Qt 在 Windows 上会让它成为父窗口的从属窗口，系统保证它始终在父窗口之上。在 Windows 11 上实测：两者的窗口所有者都是父窗口，都没有置顶样式；只有 `system` 多了置顶样式。保留两个取值是为了让意图写得明确，没有父窗口时两者都只是普通窗口。
- 默认是 `system`，对话框会一直浮在最前面。只想提示一下、不想打扰用户操作别的程序的场景，传 `none` 或 `parent`。
- `system` 用 Qt 的 `WindowStaysOnTopHint` 实现。窗口显示中切换 `stay_on_top`，Qt 会重建原生窗口，对话框会闪一下并重新显示，位置和结果码保持不变。
- 在 Windows 11 上用截图看过：系统圆角模式的对话框置顶后阴影与圆角正常；自绘圆角（透明窗口）+ 置顶的组合只验证了 `radius="md"` 的对话框能正常显示，阴影没有单独核对。

### 父窗口效果（backdrop）

`dim` / `blur` 复用 Drawer 用的共享遮罩，盖在父窗口上，父窗口缩放、移动时跟随；对话框关闭时移除。

- 遮罩只盖父窗口标题栏以下的区域：标题栏和窗口控制按钮（最小化 / 最大化 / 关闭）保持清晰可点。父窗口不是 Window（没有自绘标题栏）时盖整个客户区。
- 强度沿用遮罩的现有取值，不开放调参。
- 父窗口是自绘圆角的 Window 时，遮罩不能在圆角处露出方角。
- 没有父窗口、或 `modality="none"` 时，不做任何处理。

### 定位

`placement` 先算出对话框相对"参照区域"的位置，再加 `placement_offset`，最后钳回屏幕可见范围内。

| 情况       | 参照区域                 |
| ---------- | ------------------------ |
| 有父窗口   | 父窗口客户区             |
| 没有父窗口 | 对话框所在屏幕的可用区域 |

每次 `open()` / `exec()` 时重新计算，所以父窗口移动后再打开，对话框仍相对新位置。

## 设计说明

- **继承 Window**：`class Dialog(Window)`。`system` 风格、圆角、阴影、父子配置继承全部复用，Dialog 不重画任何外壳。
- **没有的东西**：没有 `shadow`（Window 管）、没有 `scroll_behavior`（桌面窗口没有整页滚动；内容超出上限时 body 内部自动滚动，见"自动高度"）、没有"点外面关闭"（模态时点不到外面）、没有 `xs`～`5xl` 档位（尺寸用 `width` / `height`）、没有自绘的进出场动画（系统自带窗口动画）。
- **样式决策在组件内部**：图标颜色、按钮颜色、按钮顺序都由 Dialog 决定，使用方不需要写 `if system`。
- **主题**：`theme="auto"` 跟随全局，也可固定；body 里的组件各自有自己的 `theme`，Dialog 不替它们改。

## 与 HeroUI 的关系

HeroUI v2 的 Modal 是网页遮罩层，Drawer、Popover 才是本库里"叠在宿主窗口上"的组件。桌面对话框是真正的顶层窗口，所以 Dialog 建在 Window 上，而不是照搬 Modal。README 里"Modal 由 Dialog 统一覆盖"指的就是这一点。
